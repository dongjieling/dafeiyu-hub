### 状态页

三个指示灯，各自独立：

| 灯 | 亮 = | 灭 = |
|---|---|---|
| **本地服务** | 8787 端口在监听且响应正常 | 没启动或没响应 |
| **记忆库** | LivingMemory 外部 API 连通 | 未开启 / Key 错误 / AstrBot 没开 |
| **上游模型** | 读到了 DeepSeek 的 Key | 未配置 Key |

三个都绿，才算完全就绪。

| 字段 | 说明 |
|---|---|
| 服务端口 | 默认 8787，**修改后需重启服务** |

| 打开应用时自动启动服务 | 勾选后开应用即启动 |

配置保存在 `%APPDATA%\dafeiyu-hub\config.json`。

显示：

- `[py]` 前缀：Python sidecar 的标准输出
- `[py!]` 前缀：sidecar 的错误输出（红色）

关闭窗口**不会退出**，只是隐藏到托盘。

右键托盘图标：

| 菜单项 | 作用 |

| ● 服务运行中 / ○ 服务已停止 | 状态显示（不可点） |
| 显示窗口 | 把窗口叫回来 |
| 启动服务 / 停止服务 | 控制 Python 进程 |

| 退出 | 停服务并退出应用 |

## 三、日常操作

### 启动

双击桌面「大肥鱼中转站」→ 应用启动 → 自动拉起 Python 服务（约 2 秒）。

### 确认在工作

看状态页三个灯，或访问：

```
http://127.0.0.1:8787/health
```

### 进程守护

Python 服务意外退出时，应用会**自动重启**它：

```
3 秒后自动重启（第 1/5 次）
```

连续 5 次失败后停止尝试（说明环境有问题，需要看日志）。

你自己点「停止服务」时**不会**触发重启。

### 停止

- 只停服务：状态页点「停止服务」
- 全退出：托盘右键 → 退出

### 改配置后

| 改了什么 | 要做什么 |
|---|---|
| 端口 | 停止服务 → 启动服务 |
| Python 路径 | 停止服务 → 启动服务 |
| 自动启动 | 立即生效（下次开应用） |

## 四、配置文件详解

`%APPDATA%\dafeiyu-hub\config.json`（应用层）和
`sidecar\config.json`（服务层）是两份。

### 应用层

```json
{
  "pythonPath": "C:\\...\\python.exe",
  "hubPort": 8787,
  "autoStartSidecar": true
}
```

### 服务层 `sidecar/config.json`

```json
{
  "port": 8787,
  "persona_id": "dafeiyu",
  "persona_db": "C:\\Users\\<用户>\\.astrbot\\data\\data_v4.db",
  "astrbot_config": "C:\\Users\\<用户>\\.astrbot\\data\\cmd_config.json",
  "upstream_source": "deepseek",
  "upstream_base": "https://api.deepseek.com/v1",
  "upstream_model": "deepseek-chat",
  "lm_base": "http://127.0.0.1:7801/page/external",
  "lm_key": "lm_xxx",
  "write_scope": "一号:FriendMessage:<主人QQ>",
  "recall_k": 5,
  "extract": {
    "enabled": true,
    "model": "deepseek-chat",
    "min_chars": 6,
    "min_importance": 0.3,
    "max_per_turn": 2
  },
  "archive": { "enabled": true, "db_path": "archive.db" }
}
```

| 字段 | 说明 |
|---|---|
| `persona_db` | AstrBot 主库，人格存在 `personas` 表 |
| `astrbot_config` | 从中读取 DeepSeek Key（不重复存密钥） |
| `lm_key` | LivingMemory 外部 API 密钥 |
| `write_scope` | 记忆写入的作用域，**必须填 QQ 私聊域**，否则 QQ 侧召回不到 |
| `recall_k` | 每轮召回几条记忆，默认 5 |
| `extract.min_importance` | 低于此分数的记忆不写入 |
| `archive.db_path` | 归档库文件名（实际写在数据目录） |

## 五、记忆是怎么工作的

### 读（召回）

```
用户说话
   ↓
中转站把这句话发给 LivingMemory 的 /recall
   ↓
拿回最相关的 5 条
   ↓
拼进系统提示词：「你记得关于他的事……」
   ↓
转发给模型
```

### 写（提炼）

```
对话结束（不阻塞回复）
   ↓
原文存进 archive.db（一句话都不丢）
   ↓
AI 判断：这轮有值得长期记的吗？
   ↓
有 → 写成 0-2 条要点，附重要性分数
   ↓
POST /memories 写回 LivingMemory
```

### 分层

| 层 | 存哪 | 用途 | 参与检索 |
|---|---|---|---|
| 原文 | 本地 `archive.db` | 回溯、重建 | ❌ |
| 要点 | LivingMemory | 语义检索 | ✅ |

## 六、接入客户端

### AIRI（桌面宠物）

设置 → 服务来源 → 聊天 → OpenAI 兼容：

| 字段 | 值 |
|---|---|
| Base URL | `http://127.0.0.1:<端口>/v1`（默认 8787） |
| API Key | `local`（任意，不为空即可） |
| 模型 | 状态页显示的上游模型 |

### AstrBot（QQ 机器人）

模型提供商 → 新增 OpenAI 兼容：

| 字段 | 值 |
|---|---|
| Base URL | `http://127.0.0.1:<端口>/v1`（默认 8787） |
| API Key | `local`（任意，不为空即可） |
| 模型 | 状态页显示的上游模型 |

> 端口和模型都以应用内「状态」「配置」页为准，不要照抄示例。

⚠️ AstrBot 走中转站后，它自己的记忆插件会重复记录。二选一：
- 要么 AstrBot 直连模型（本项目的当前假定）
- 要么关掉 AstrBot 自己的记忆注入

## 参数页

左侧「参数」，分两块：上面是中转站自己的，下面是 AstrBot 插件的。

### 中转站参数

| 参数 | 作用 | 建议 |
|---|---|---|
| 每轮召回条数 | 注入多少条记忆 | 5–8 |
| 启用记忆提炼 | 要不要把对话写回记忆库 | 开 |
| 写入最低重要性 | 低于此分数不记录 | 0.3–0.5 |
| 每轮最多写入条数 | 防止记忆碎片化 | 1–2 |
| 触发提炼的最短字数 | 太短的话不提炼 | 6 |
| 启用知识库检索 | 是否查知识库 | 按需 |
| 知识库返回条数 | 每次取几段 | 3–5 |

保存后会**自动重启服务**。

### 插件参数

每个插件卡片右上角有状态标签：

| 标签 | 含义 |
|---|---|
| 已安装 | 可以调 |
| 未安装 | 没装这个插件，参数不可调 |
| 版本不符 | 版本低于要求，先升级 |
| 缺少配置 | 插件还没生成配置文件 |

保存流程：**自动备份 → 写入 → 重载插件**。
日志里能看到「已保存 xxx 参数（备份 …）」「xxx 已重载生效」。

支持的插件：

| 插件 | 可调项 |
|---|---|
| LivingMemory | 召回条数、最低相似度、写入频率、记忆原子开关、外部 API 开关/端口 |
| 情绪管理 | 初始好感、对他热情/攻击性、敏感度、衰减时长 |
| 主动消息 | 私聊开关、自动触发、间隔、免打扰、未回复上限 |

### 状态页的主题与版本

- 左下角「深色 / 浅色」切换，选择会记住
- 左下角显示应用版本；状态页「服务版本」显示 Python 服务版本

## QQ 对话归档同步

中转站会把 QQ 侧的原始对话**增量导入**归档库，这样归档才是完整的。

配置（`config.json` 的 `archive` 段）：

```json
"archive": {
  "enabled": true,
  "db_path": "archive.db",
  "retention_days": 0,
  "sync_qq": true,
  "sync_interval_seconds": 300,
  "qq_source_db": "C:\\Users\\<用户名>\\.astrbot\\data\\plugin_data\\astrbot_plugin_livingmemory\\conversations.db"
}
```

| 字段 | 说明 |
|---|---|
| `sync_qq` | 是否开启 QQ 侧同步 |
| `qq_source_db` | AstrBot 的原始对话库路径（LivingMemory 插件目录下） |
| `sync_interval_seconds` | 同步间隔，默认 5 分钟 |
| `retention_days` | 原文保留天数，0 = 永久 |

行为：

- 启动 5 秒后跑第一次，之后按间隔跑
- 用游标记录进度，只导新消息
- 日志会显示「QQ 归档同步: 新增 N 条（游标 X）」

归档库里的消息按来源区分：`source='qq'` 和 `source='airi'`。

## 记忆写入失败会自动重试

写回记忆库失败时不再直接丢弃：

1. 记入 `extractions` 表，状态 `failed`
2. 后台每 60 秒重试一次，最多 3 次
3. 重试用同一幂等键，不会产生重复记忆

日志会显示「重试成功 / 重试失败（第 N 次）」。

## 日志默认不含对话内容

```json
"logging": { "log_content": false }
```

关闭时只记录「召回 8 条」「知识库命中 3 条」，不记录具体内容——避免私密对话被写进日志。

排查问题时想看到内容，临时改成 `true` 即可。

## 归档加密

归档库（`archive.db`）里的消息内容默认**加密存储**。

### 加密了什么

| 字段 | 是否加密 |
|---|---|
| 消息内容 | ✅ AES-256-GCM |
| 消息元数据（发送者、群号…） | ✅ |
| 提炼记录文本 | ✅ |
| 会话 ID、时间戳 | ❌（结构字段，不加密） |

密文格式：`enc:v1:<base64>`。旧的明文记录会在迁移时自动加密。

### 密钥在哪

```
%APPDATA%\dafeiyu-hub\archive.key
```

- 32 字节随机密钥
- 用 **Windows DPAPI** 绑定当前账户后落盘
- 程序启动时自动解密，使用无感

### 能防什么、不能防什么

| 场景 | 是否防住 |
|---|---|
| 文件被拷走（网盘、U 盘、备份） | ✅ |
| 硬盘送修、电脑丢失 | ✅（配合 BitLocker 更好） |
| 同账户下的程序读取 | ❌（DPAPI 绑定的是账户，不是密码） |
| 进程内存被转储 | ❌ |
| 中了木马 | ❌ |

### 换电脑 / 换 Windows 账户

DPAPI 密钥绑定当前账户，**换账户后旧库解不开**。

迁移前先导出密钥：

两种方式：

1. **界面**：配置页 → 「导出归档密钥」→ 选保存位置
2. **命令行**（有源码时）：

```powershell
python src\sidecar\crypto.py --export D:\archive.key.bak
```

恢复时把 `archive.key.bak` 放回 `%APPDATA%\dafeiyu-hub\archive.key`。

> ⚠️ 导出的密钥文件是**未加密**的，请离线保存（不要放网盘、不要和归档库放一起）。

### 关掉加密

```json
"archive": { "encrypt": false }
```

关闭后新写入是明文；已有密文仍可正常读取。

## 连通性自检

状态页顶部有「连通性自检」，点一下会依次检查：

| 步骤 | 检查内容 | 失败时的含义 |
|---|---|---|
| 配置完整 | `lm_key` / `persona_db` / `write_scope` | 还没填配置 |
| 记忆库在线 | LivingMemory `/health` | 插件没开或端口不对 |
| 写入测试记忆 | 写一条带标记的测试数据 | Key 无效或写入被拒 |
| 检索回测试记忆 | 最多等 25 秒 | 索引没建好（或嵌入模型不可用） |
| 知识库检索 | 启用知识库时检查 | 面板密钥或库名不对 |

每步显示耗时，全部通过才显示「全部通过」。

### 清理测试数据

自检写入的记忆带固定标记 `【自检】SELFTEST-xxxx`。
点「清理测试数据」会删除所有带这个标记的记忆，连带清理原子、图谱条目、孤立节点。

> 注意：记忆库插件不提供删除接口（`DELETE` 返回 405），
> 所以清理是直接操作数据库文件，**建议先备份**。
> 只会删带 `【自检】` 标记的数据，不会碰正常记忆。

### 命令行方式

```powershell
curl.exe -X POST http://127.0.0.1:8787/v1/selftest
curl.exe -X POST http://127.0.0.1:8787/v1/selftest/cleanup
```

## 人格降级提示

v1.0.0 起，人格有四层来源：

| 顺序 | 来源 | 触发 | 界面 |
|---|---|---|---|
| 1 | AstrBot 数据库 | 正常 | 绿 |
| 2 | 上次成功缓存（LKG） | 暂时读不到 | 黄条「人格使用缓存」 |
| 3 | 包内精简版 | 从未成功读过 | 红条「人格未正常加载」 |
| 4 | 内置常量 | 精简版也缺失 | 红条 |

- 缓存超过 24 小时未更新 → 黄条转红条
- 缓存用 DPAPI 加密（`persona.lkg.bin`），换 Windows 账户后失效
- 人格永远不会静默为空

## 流水线卡片

状态页「最近流水线」显示每轮卡在哪一层：

```
21:36:12 upstream ok 2828ms · model=deepseek-chat msgs=3
21:36:13 archive ok 25ms · mid=2394
21:36:14 extract ok 1068ms · 2 条
21:36:15 enqueue ok 1674ms · 2 条
```

最后失败会以红色显示在标题右侧；完整的最近事件也能从 `/health.pipeline` 取到。

## 写入队列（outbox）

```
pending → sending → written → verified
              ↓
           failed → dead（5 次后）
```

- 聊天线程只入队，后台 worker 负责发送
- 进程崩溃后，卡在 `sending` 的记录会自动放回队列
- 写入后 45 秒验证一次可检索；未确认会标 `index_unconfirmed`（写入本身是成功的）

## 去重与作用域

- 写之前先查本地历史 + 召回，相似度 ≥ 0.88 跳过，状态记 `duplicate`
- 召回只取 `write_scope` 本域，避免群聊记忆串进私聊
