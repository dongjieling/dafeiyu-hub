# 路线图 v1.0.0

> 状态：**规划完成，未开工**
> 上一个可用版本：v0.4.7

---

> 本路线图按 ADR-001 修订版（含 6 点评审修订）编写。

## 一句话

v1.0.0 不是加功能，是让这条记忆链路**从"能跑"变成"能长期维护"**。

---

## 包含什么

| 阶段 | 内容 | 工期 | 解决的事故 |
|---|---|---|---|
| 1a | 契约层 + 人格三级降级（DB/LKG/fallback）+ 三级严重度 + 最小 CI | 0.5–1 天 | 人格静默为空 |
| 1b | 记忆适配器 + schema 迁移 + write_scope 校验 + PatchManager | 1–1.5 天 | 新装缺列、老库升级、写错域、补丁丢失 |
| 二期 | outbox（写入不丢） | 2 天 | 崩溃丢记忆、重试过期 |
| 三期 | E2E 契约测试 + CI | 1–2 天 | 24 小时 8 版本 5 回归 |
| 四期 | 可观测（结构化事件） | 1 天 | 排查靠猜 |
| 五期 | 质量（去重 / 域隔离 / 重要度） | 3–4 天 | 泛问不准、跨域噪声 |

合计 **9–11 天**。

---

## 不包含什么

| 不做 | 原因 |
|---|---|
| 换框架 | Electron + Python 够用 |
| 重写检索 | LM 的混合检索更强 |
| 多用户 / 权限 | 个人使用 |
| 自动更新 | 手动下载即可 |
| MCP 输出 | 独立特性，v1.1 再说 |
| 协议端适配（NapCat 替代） | 独立议题，需要单独调研 |

---

## 版本策略

```
v0.4.7   当前（冻结功能）
v0.4.x   只修阻断性缺陷
v1.0.0   六段全部完成，一次性发布
```

中途不发 0.5 / 0.9：契约改到一半发布，用户会遇到新旧混用的中间态。
