# ADR-003 三条架构缝：ClientContext、durable turns、MemoryStore

> 状态：部分实施（v1.6.0 落地前两条，MemoryStore 待做）
> 日期：2026-11-28

## 背景

代码评审指出三个天花板：

1. `dict` 传 cfg，client/scope/persona 没有统一上下文
2. 提炼依赖 daemon 线程，崩溃会丢“这一轮”
3. 记忆读写散落在 5 个模块，直接写 LM SQLite，没有存储抽象

v1.6.0 先修前两条，第三条留作下一版。

## 决策 1：ClientContext

`clients.py` 新增 frozen dataclass：

```python
ClientContext(id, name, token, scope, persona_id, model,
              temperature, recall_k, allow_write, enabled)
```

- `authenticate()` 返回 `ClientContext`，不再是裸 dict
- 保留 `.get()` / `[]`，老的 `cfg` 代码可以渐进迁移
- `effective_cfg(base, client)` 仍负责生成请求级 cfg，边界从这里开始收

**未做**：把 `extractions/messages/sessions` 全量迁移到 client_id 列；
`extractions` 已有 client_id，归档会话用 `client:<id>` 区分。

## 决策 2：durable turn

新增 `turns.py` 与 `turns` 表：

```sql
id, client_id, scope, persona_id, message_id,
user_text, reply_text, trace,
status(pending/processing/queued/skipped/duplicate/failed),
attempts, next_at, error, created_at, updated_at
```

流程：

```
回复生成 → capture（落盘 turn + 归档原文）→ 异步 process_one
崩溃 → 重启 recover：processing → pending
解析失败 → 最多 3 次，60 秒退避
```

- `schedule_memory_job` 只负责 capture + 起线程，不再在内存里做提炼
- `turns.start()` 每 5 秒扫 pending
- 归档保留天数同时清理已完成的 turn

**边界**：outbox 仍负责“已提炼 → 写入 LM”的可靠投递；
turn 负责“每轮对话不丢”。

## 决策 3：MemoryStore（待做）

目标接口：

```python
class MemoryStore(Protocol):
    def recall(query, scope, k) -> list[Memory]
    def list(filters) -> Page
    def write(item, client, scope) -> str
    def delete(memory_id) -> bool
    def range(start, end, scope) -> list[Memory]
```

实现：

- `LivingMemoryHttpStore`：只走 LM HTTP API（正常路径）
- `SqliteMaintenanceStore`：只给删除/清理/体检用（明确标注 maintenance）

迁移顺序：

1. `memories.py` 的 list/delete → store
2. `memory.range_memories` → store（需要 LM API 支持日期过滤，否则保留 SQLite + 标注）
3. `mcp_server` / `hub.memory_health` → store
4. `selftest` / `patch_manager` → store 或明确 maintenance

**不在 v1.6.0 做**：避免一次改动过大，先让 turn/上下文稳定。

## 后续模块拆分（P1）

- `memory.py` → `recall.py` / `extract.py` / `archive.py` / `maintenance.py`
- `hub.py` → 路由表 + `api/chat.py` / `api/admin.py` / `api/mcp.py`
- `renderer.js` → 按页面拆模块（最后做）

## 后果

- 多客户端请求有明确上下文对象，后续加字段不用再改一堆函数签名
- 崩溃丢轮次的窗口从“提炼线程”缩到“turn 落盘前”，可恢复
- MemoryStore 未做之前，LM 插件升级仍需要改多处；这是下一版的主要风险
