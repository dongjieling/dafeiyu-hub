# 常见问题

按现象查。

---

## 一、启动类

### 双击 EXE 没反应

| 排查 | 方法 |
|---|---|
| 目录权限 | 换到 `D:\` 下普通目录 |
| 被杀毒拦 | 安全软件里加白名单 |
| 缺 Python | 配置页填对路径 |

### 窗口一闪就关

如果是 `.bat` 启动脚本：文件必须是 **CRLF 换行 + ASCII 编码**，
否则 `cmd` 会把 `cd /d` 拆开报错。

### 托盘图标没出现 / 弹错误框

图标文件损坏会导致 Tray 创建失败。本项目的做法：

- 图标用 Python 的 Pillow 生成，不用手写 base64
- 找不到图标时用 1×1 透明图兜底

## 二、连接类

### 记忆库灯不亮

依次检查：

| # | 检查 | 方法 |
|---|---|---|
| 1 | 7801 端口在监听吗 | `Get-NetTCPConnection -LocalPort 7801` |
| 2 | 插件的外部 API 开了吗 | AstrBot 面板 → LivingMemory 配置 |
| 3 | 插件重载了吗 | 改配置后必须重载 |
| 4 | Key 对吗 | `curl http://127.0.0.1:7801/page/external/health -H "Authorization: Bearer lm_xxx"` |

### 上游模型灯不亮

中转站从 AstrBot 的 `cmd_config.json` 里读 DeepSeek Key。
路径填错就读取不到。

检查：

```powershell
# 路径是否存在
Test-Path "C:\Users\<用户名>\.astrbot\data\cmd_config.json"
```

### 客户端连不上中转站

| 现象 | 原因 |
|---|---|
| 连接被拒绝 | 服务没启动 |
| 返回 500 | 中转站读不到上游 Key |
| 返回 404 | 地址少了 `/v1` |

正确地址：`http://127.0.0.1:8787/v1`

## 三、记忆类

### 她说不记得

可能原因：

| 原因 | 排查 |
|---|---|
| 记忆没写进去 | 看 `hub.log` 有没有「写回记忆」 |
| 作用域不对 | 见下方「作用域」 |
| 召回门槛太高 | LivingMemory 的 `min_similarity_for_retrieval` |
| 问题跟记忆太不像 | 换个问法 |

### QQ 看不到桌宠写的记忆（重点）

**这是作用域问题。**

实测结论：

| 召回时传的 scope | 能看到桌宠写的吗 |
|---|---|
| `airi:desktop` | ✅ |
| `一号:FriendMessage:<主人QQ>` | ❌ |
| 不传 | ✅ |

所以 `sidecar/config.json` 里的 `write_scope` **必须填 QQ 私聊域**：

```json
"write_scope": "一号:FriendMessage:123456789"
```

格式：`<平台名>:FriendMessage:<QQ号>`

平台名在 AstrBot 的平台配置里能看到（默认可能叫「一号」）。

### 记忆越记越乱

| 手段 | 做法 |
|---|---|
| 提高入库门槛 | `extract.min_importance` 调到 0.5 |
| 减少每轮条数 | `extract.max_per_turn` 设为 1 |
| 靠衰减清理 | LivingMemory 的 `importance_decay` |
| 手动清理 | 面板里删除低分记忆 |

### 写入了「她关心他」这种条目

提示词要求第三人称写「他」，但模型偶尔跑偏描述 AI 自己。
本项目已加过滤：以「她 / 我 / 你」开头的条目直接丢弃。

## 四、流式类

### 客户端一直等到超时

**原因**：流式响应结束后没有关闭连接，客户端等 EOF 无果。

**修复**（已包含在 v0.1.0）：

```python
self.close_connection = True
self.send_header('Connection', 'close')
```

### 流式没有打字机效果

客户端可能把 `stream: true` 写成了字符串 `"true"`。
必须是布尔值。

## 五、日志类

### 日志被健康检查刷屏

界面每几秒轮询 `/health`，如果照常记录会淹没真实事件。
本项目已过滤 `/health` 与 `/v1/models`，且 LM 探测加 15 秒缓存。

### 日志在哪

| 文件 | 内容 |
|---|---|
| `%APPDATA%\dafeiyu-hub\main.log` | Electron 主进程 |
| `%APPDATA%\dafeiyu-hub\hub.log` | Python sidecar |
| `sidecar\hub.log`（旧版） | v0.1.0 之前的位置 |

## 六、数据类

### 数据存在哪

`%APPDATA%\dafeiyu-hub\`：

```
├── config.json     应用配置
├── archive.db      原文归档 + 提炼记录
├── hub.log         sidecar 日志
└── main.log        应用日志
```

### 换机器怎么迁移

1. 复制程序目录
2. 复制 `%APPDATA%\dafeiyu-hub`
3. 检查 `sidecar/config.json` 里的路径是否需要改用户名

### 归档库能重建记忆吗

能，但**向量要重算**。

`archive.db` 里是原文，记忆库需要重新走一遍提炼 + 嵌入。
最省事的做法是保留旧机器的 `livingmemory.db`，直接复制过去。

## 九、召回质量类（实测记录）

### 明明写在记忆库里，桌宠却说不知道

按顺序排查：

| # | 检查 | 方法 |
|---|---|---|
| 1 | 记忆真的写进去了吗 | 搜 `livingmemory.db` 的 `documents` 表 |
| 2 | 写入多久了 | 新记忆要 **30–60 秒**索引后才可检索 |
| 3 | 召回查询被污染了吗 | 看 `hub.log` 的「召回查询」行 |
| 4 | 是不是被长历史带跑了 | **开新对话**再问 |

### 桌宠发来的消息夹带垃圾（重要）

桌面宠物（AIRI）发消息时会自动加三类东西：

```
[2026-11-24 16:08] 那我今天体测跑了多少米     ← 时间戳
[Context]                                     ← 运行时上下文块
- system:airi-runtime-prompt
<|ACT {"emotion":"awkward"}|><|DELAY 1|>      ← 动作/表情标记
```

拿整坨去检索，语义会被污染，召回到毫不相关的记忆。

**本项目已内置清洗**（`clean_query`）：

- 去掉开头的 `[日期 时间]`
- 截断 `[Context]` 之后所有内容
- 剥掉 `<|...|>` 标记

如果你想自己写网关，这段逻辑一定要抄。

### 之前说「不知道」，现在一直说不知道

**长历史锚定效应**：模型看到自己前面说过"不知道"，会延续这个结论，哪怕记忆已经注入了。

两种解法：

| 解法 | 说明 |
|---|---|
| 开新对话 | 最有效，清掉历史包袱 |
| 把记忆放到最后一条用户消息之前 | 本项目采用，靠近提问位置，且措辞用「你现在想起来了」并显式要求「不要因为之前说过不知道就继续不知道」 |

### 具体细节查不到（只记得大概）

召回条数太少会导致细节被截断。调大 `recall_k`：

```json
"recall_k": 8
```

默认 5 条，实测 8 条能明显改善"只知道大方向、不知道细节"的问题。

### QQ 那边说的，桌宠很久才知道

AstrBot 的 LivingMemory 是**批量写**，不是每轮写。

配置项：

```json
"reflection_engine": { "summary_trigger_rounds": 10 }
```

改成 2 后，聊两句就会同步一次。代价是 LLM 调用次数变多。

⚠️ 改完要**重载插件**才生效；重载后需要**有新的 QQ 消息**才会触发一次总结。
