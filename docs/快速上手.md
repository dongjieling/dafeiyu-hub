# 快速上手

> 装好之后怎么用。约 5 分钟读完。

---

## 一、每天开机的顺序

```
1. NapCat（双击 napcat.bat，扫码/自动登录 QQ）
2. AstrBot（桌面图标，一般已开机自启）
3. 大肥鱼中转站（桌面快捷方式）
4. AIRI 桌宠（D:\AIRI\airi.exe）
```

⚠️ **顺序不能反**：中转站要从 AstrBot 的数据库读人格，AstrBot 没开就读不到。

## 二、看窗口

打开中转站，主界面是这样：

```
┌──────────────┬────────────────────────────────────┐
│              │ 状态        [启动服务][停止服务][检测] │
│ 状态          │                                    │
│ 配置          │ ● 服务运行中                        │
│ 日志          │                                    │
│              │ ┌────────┐┌────────┐┌────────┐      │
│              │ │本地服务 ││ 记忆库 ││上游模型│      │
│              │ └────────┘└────────┘└────────┘      │
└──────────────┴────────────────────────────────────┘
```

### 三个灯 = 三个体检项

| 指示灯 | 亮 | 灭 |
|---|---|---|
| 本地服务 | 8787 在监听 | 服务没启动 |
| 记忆库 | 连上了 LivingMemory | 记忆插件没开 / Key 错 |
| 上游模型 | 读到了 DeepSeek Key | 没配 Key |

| 亮几个 | 能不能用 |
|---|---|
| 3 个 | ✅ 完整功能 |
| 2 个 | ⚠️ 缺一块，看哪个灭了 |
| 0–1 个 | ❌ 先修，别急着聊 |

哪个灭了就点左侧「日志」看原因。

## 三、关窗口 ≠ 关程序

点 `×` 只是**缩到托盘**（右下角蓝色小图标）。

| 想做的事 | 操作 |
|---|---|
| 暂时不用但保持后台 | 点 `×` |
| 把窗口叫回来 | 双击托盘图标 |
| 真正退出 | 托盘右键 → 退出 |
| 只停服务不停程序 | 状态页 → 停止服务 |

托盘右键菜单：

```
● 服务运行中 / ○ 服务已停止
─────────────
显示窗口
启动服务 / 停止服务
─────────────
打开日志文件夹
退出
```

## 四、怎么跟她说话

桌宠（AIRI）里直接打字。她的语气、人格、记忆都来自中转站。

### 怎么让她记住

**有效的说法**（稳定的事实）：

```
我下周三要去医院复查
我最近在写一个项目，天天加班到十一点
我不吃香菜
```

**无效的说法**（不会被记）：

```
嗯
在吗
哈哈
习惯了
```

规则：**超过 6 个字、含具体信息** 才会进入提炼流程。

### 怎么验证她记住了

等约 10 秒，然后问：

```
我下周三要干嘛
```

答出「复查」= 记忆链路通。

## 五、记忆是怎么流转的

```
你说话
  ↓
【召回】从中转站找出相关的 5 条旧记忆
  ↓
连同人格一起发给 DeepSeek
  ↓
她回答（此时"记得"）
  ↓
【后台异步】原文存归档库 → AI 提炼要点 → 写回记忆库
```

**写入是异步的**，慢 10 秒左右。刚说完立刻问，可能还没落库。

### 她记岔了怎么办

| 现象 | 处理 |
|---|---|
| 记错了 | 直接在对话里纠正：「不是养猫，是养狗」，新记忆会盖过旧的 |
| 记了太多废话 | 说「以后别记这种」，或调高 `min_importance` |
| 完全不记 | 看日志有没有「写回记忆」 |

## 六、看日志排障

日志在：

```
%APPDATA%\dafeiyu-hub\hub.log
```

或者窗口里点「日志」页。

关注这几个关键词：

| 日志行 | 含义 |
|---|---|
| `召回 N 条记忆` | 读记忆正常 |
| `写回记忆: xxx` | 写记忆成功 |
| `召回失败` | 记忆库连不上 |
| `上游 HTTP 401` | API Key 无效 |
| `上游 HTTP 402` | 余额不足 |
| `服务退出` | Python 进程挂了 |

## 七、常见故障速查

| 症状 | 先检查 | 处理 |
|---|---|---|
| 桌宠完全不回话 | 三个灯 | 服务没启动 → 点「启动服务」 |
| 回话但很机械 | 记忆库灯 | 人格没读到 → 查 `persona_db` 路径 |
| 说不记得 | `hub.log` 的召回行 | 没召回 → 问题太不像 / 记忆没写入 |
| QQ 看不到桌宠的记忆 | `write_scope` | 必须填 QQ 私聊域 |
| 401 / 402 | 上游灯 | Key 失效或余额不足 |

## 八、两个最容易踩的坑

### 坑 1：中转站没启动，以为桌宠坏了

桌宠连的是 `127.0.0.1:8787`，中转站不开就是连不上。

**表现**：桌宠一直转圈或不说话。

### 坑 2：作用域配错，QQ 看不到桌宠的记忆

`sidecar/config.json` 里：

```json
"write_scope": "一号:FriendMessage:123456789"
```

这一行必须是 **QQ 私聊域**（`<平台名>:FriendMessage:<QQ号>`），
否则 QQ 侧召回不到桌宠写的内容。

## 十、三条排障命令

```powershell
# 1. 服务活着吗
curl http://127.0.0.1:8787/health

# 2. 记忆库活着吗（换成自己的 Key）
curl http://127.0.0.1:7801/page/external/health `
  -H "Authorization: Bearer lm_你的key"

# 3. 谁占了 8787
Get-NetTCPConnection -LocalPort 8787 -State Listen
```
